"In our project, we followed a Git Flow–based workflow. Developers created feature branches from the develop branch for every new feature or bug fix. After development, they raised a pull request, which was reviewed and merged into develop. Jenkins automatically triggered the CI pipeline to build, test, scan, and deploy the application to the development environment. After successful validation, the same code was promoted through QA, Stage/UAT, and finally Production using separate Jenkins pipelines with environment-specific Helm values. As DevOps engineers, we followed the same branching process for infrastructure changes such as Jenkinsfiles, Helm charts, ConfigMaps, Kubernetes manifests, and Terraform code. Every infrastructure change was implemented in a feature branch, reviewed through a pull request, approved, merged, and then deployed automatically through the CI/CD pipeline."
